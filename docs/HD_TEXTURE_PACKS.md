# HD texture packs

Tomba's **HD Texture Packs** mod loads compatible DuckStation texture PNGs and
can dump the original textures encountered while you play. The mod is disabled
by default. Use **OpenGL** to display replacements; the software and Vulkan
renderers can collect dumps but do not display HD replacements.

## Try the included example

The [optional Tomba example](../examples/hd-texture-pack/README.md) contains
five synthetic cyan/magenta checkerboards and a drop-in `mods` directory. Copy
its `mods` folder beside the game executable, enable **HD Texture Packs**, and
use **OpenGL**. The title logo gives an obvious visual check. This example
contains no original artwork or dumps and does not enable the mod automatically.
Its [Tomba pack-directory README](../examples/hd-texture-pack/mods/texture-packs/SCUS-94236/README.md)
travels with the pack and explains capture, editing, compatibility, and removal.

Linux AppImage users copy the example into the writable data root
`${XDG_DATA_HOME:-$HOME/.local/share}/TombaRecomp` or `TOMBA_RECOMP_DATA_DIR`;
the AppImage payload itself is read-only. Keep an existing pack separate to
avoid overwriting your artwork.

## Install a pack

1. Start TombaRecomp and open **Mods**.
2. Enable **HD Texture Packs**.
3. Under **Texture pack folder**, click **Open folder**. On first use the
   launcher creates `mods/texture-packs/SCUS-94236` beside the executable, with
   empty `replacements` and `dumps` directories.
4. Extract the pack's replacement PNGs into `replacements`. Preserve their
   filenames. Subdirectories are allowed. If the download already contains a
   `replacements` directory, copy its contents into this directory.
5. Leave **Load replacements** enabled and **Dump textures** disabled. Choose
   **OpenGL** in Settings, then click **Play**.

Use **Change folder** to select another pack root. An empty selected directory
is valid; the runtime creates its `replacements` and `dumps` directories.
Selecting an existing pack's `replacements` directory directly is also
supported, with `dumps` beside it. Keep your pack outside `mods/bundled`: that
directory is regenerated by builds and updates.

## Create a pack from gameplay

1. Open **Mods**, enable **HD Texture Packs**, and click **Open folder** to find
   the capture directory.
2. Disable **Load replacements** and enable **Dump textures**.
3. Click **Play** and visit the levels, menus, and scenes whose artwork you
   want to replace. Newly encountered original textures are written as PNGs
   under `dumps`; dumping does not change game textures in VRAM.
4. Exit to the launcher. Copy the PNGs you want to edit from `dumps` into
   `replacements`, then edit or enlarge them while retaining their filenames.
   Keep the source aspect ratio and an integer size multiplier.
5. Enable **Load replacements**, disable **Dump textures**, and click **Play**
   using OpenGL to check the result.

The dump and replacement switches apply on **Play**. Restart after adding or
editing pack files so the runtime scans the folder again. Disable the mod to
return to the original artwork. Existing saves remain usable.

## Compatibility

The runtime implements the DuckStation filename/hash conventions independently.
This is format compatibility, not a bundled copy of DuckStation. No original
game artwork or third-party pack artwork is supplied with the mod.

Texture matching depends on the original pixels and palettes encountered by
the game, so a pack for a different game region or disc revision may not match.
Unmatched textures retain their originals. PNG is the supported image format;
JPEG and WebP are unsupported. Images may be at most 8192 pixels on either
side, 64 MiB encoded, and 64 MiB decoded as RGBA. Advanced pack coalescing,
copy/split identities, multi-image composition, and wrapped texture footprints
are unsupported and fall back to original artwork.

After loading a savestate, upload-based replacements need fresh texture
uploads from the game before they can match again. Page-based matching remains
available.

See the framework's
[DuckStation texture format notes](../psxrecomp/docs/DUCKSTATION_TEXTURE_FORMAT.md)
for exact naming, hashing, alpha, and configuration support. The first target
for this workflow is the USA release, `SCUS-94236`.

## Development validation

Build with `-DPSX_DEBUG_TOOLS=ON` and launch the isolated test executable with
`--debug-port 4478`. After visiting a textured scene, run:

```sh
python tools/check_hd_texture_pack_session.py --expect-dumps --report capture.json
```

The probe checks the active dump switch, queued capture count, PNGs actually
written, and their dimensions. After adding a visible test replacement and restarting,
run it with `--expect-replacements` to verify matching, decoded readiness, and
actual OpenGL draw submissions. Use `--expect-inactive` after disabling the mod
to verify that a prior pack does not remain active. Capture a screenshot as
well to assess visual placement and blending; counters alone do not prove
image quality. Run development tests with their own config and memory cards.

Development builds also expose the `hd_textures` TCP command. A plain query
reports the selected root, requested switches, backend support, and draw
counters. Optional integer fields `replacements: 0|1`, `dump: 0|1`, and
`reload: 1` control the configured host pack in a running test session; reload
rescans edited PNGs while preserving unchanged upload identities. These
controls never write replacement pixels into native VRAM. Use `present_shot`
to capture the composed OpenGL window; native VRAM screenshots deliberately
retain the original artwork.
